# Working on DAW

Read README.md, docs/PROTOCOL.md, and the selected ticket in docs/PLAN.md before editing. The current product has a browser GUI with live sine audition and Rust WAV export, plus optional macOS native playback through JSONL, the GUI, and CLI; schema-v2 note sequencing and preloaded PCM WAV clips are available through scripts and rate-matched native playback. Schema-v3 adds serial track gain effects, bypass, and saved step/hold gain automation. Schema-v4 adds optional macOS scripted offline VST3 effects through owned workers (`vst3-offline`); schema-v5 adds optional macOS offline AUv2 processing through an owned worker (`au-offline`), restricted to Apple AULowpass. Both plugin render paths require 48 kHz and stop at ten seconds. Optional `vst3-live` adds experimental in-process native VST3 effects through an owned DSP worker and fixed callback queue. Plugin sessions require a 48 kHz device and do not support seek/loop. The browser editor supports v1 and schema-v4 continuous sine tracks, gain chains, and controls/reuse for VST3 effects loaded from validated saved sessions; it rejects schema-v5 imports. Schema-v6 GUI support covers continuous sine/SuperCollider sources with gain-only chains, inspected saved control arrays and native live Play/Stop; program/duration/automation remain scripted. Notes/audio clips and v2/v3 editing remain unsupported; plugin discovery/windows and AU live playback are not implemented. Keep that distinction in capabilities and user-facing documentation.

- Implement one bounded ticket per logical commit. Use `type(scope): description`, stage only the task's files, and push working states when authentication is available. Use a `codex/` branch for risky changes.
- Prefer GPT-6 Luna for bounded examples, tests, documentation, and straightforward commands. Parallelize independent files when useful. One agent owns integration and shared file edits. Native hosting, real-time concurrency, and schema design need a stronger model's review.
- Preserve versioned JSON contracts and structured errors. Validate fully before changing the active session. Never overwrite outputs implicitly. Stdout belongs to the protocol.
- Do not add speculative format stubs, generic processor traits, or unimplemented commands that claim success. Establish an interface from a second working adapter.
- No allocation, locks, filesystem/network access, subprocess startup, or foreign-code initialization in future audio callbacks. The current offline renderer is not suitable for direct callback use.
- Run `cargo fmt --check`, `cargo clippy --locked --all-targets -- -D warnings`, and `cargo test --locked`. For a client change, also run `cargo build --locked` and `python3 examples/demo.py`. Use `--offline` with an available cache when networking is unavailable.
- Keep generated audio under ignored `output/`. Do not commit recordings, temporary app state, credentials, or plugin binaries.
- For live-player changes, run `node --test gui/test_live.cjs gui/test_editor.cjs`. Browser audition is separate from native engine capabilities; do not claim browser plugin support.
- For GUI changes, run `python3 -m unittest gui.test_server` and exercise the browser against the real Rust engine. The Python bridge requires Python 3.10+ and loopback socket access. Keep HTTP file access constrained to browser uploads/downloads, preserve per-launch token/host/origin checks, and keep the Rust model authoritative.
- Update ticket status, protocol examples, and limitations with the change. Record unverified platform behavior honestly. Routine reversible implementation needs no extra approval.

- For VST3 worker/session changes, build `python3 native/vst3/build.py`, run combined `vst3-offline,native-audio` Rust checks, and run `python3 -m unittest native.vst3.test_daw native.vst3.test_metadata`. - For native-audio changes on macOS, also run `cargo clippy --locked --features native-audio --all-targets -- -D warnings` and `cargo test --locked --features native-audio`. - For live VST3 changes, also run `cargo clippy --locked --features vst3-live --all-targets -- -D warnings`, `cargo test --locked --features vst3-live`, and `python3 -m unittest native.vst3.test_live native.vst3.test_parameters`. - SuperCollider NRT jobs use `supercollider.render` on Unix with explicit `DAW_SCSYNTH`. `supercollider.inspect` adds portable bounded SCgf-v2 metadata/graph inspection without claiming runtime compatibility. NRT jobs are synchronous standalone score jobs; schema-v6 embeds saved SynthDefs/controls/events and prepares finite float PCM before session commit/native playback. Interactive OSC/DSP and GUI imports remain unimplemented. Run `python3 -m unittest native.supercollider.test_daw native.supercollider.test_inspect native.supercollider.test_sources native.supercollider.test_routing` and `DAW_SCSYNTH=/absolute/scsynth python3 examples/supercollider_demo.py`. Preserve score snapshots, owned process groups, bounded diagnostics/deadlines and exclusive output publication; do not claim NRT export is live runtime integration.

- SuperCollider source changes preserve portable schema-v6 parsing and prepared-cache freshness. Saved native bases (including arrays and frame-zero overrides) are supplied at synth creation; known initialization-rate controls reject later points. Runtime float PCM shares asset budgets, and its preparation must finish outside callbacks and before a live VST3 DSP worker starts. The two-track demo supports `--native` as a silent host smoke test; `DAW_TEST_NATIVE_AUDIO=1` enables source/native routing tests.
