## Research findings

libpd is the upstream embeddable C API for Pure Data. Its header exposes initialization, explicit abstraction/external search paths, patch open/close, audio setup, fixed block-size query, and interleaved float processing. `libpd_process_float(ticks, in, out)` sizes each buffer as `ticks * libpd_blocksize() * channels`; success is zero. A one-tick stereo call is suitable for DAW's 64-frame blocks only when `libpd_blocksize()` reports 64. The API does not let the caller select an arbitrary tick size, so a build/runtime mismatch must fail clearly rather than adapt blocks silently. See the [upstream C API](https://github.com/libpd/libpd/blob/master/libpd_wrapper/z_libpd.h).

`libpd_init()` clears the extra search paths and changes SIGFPE handling. libpd has no default extra search paths; relative paths resolve from the process working directory. The host should initialize once, set any process signal policy afterward, then add only explicit private paths before opening a patch by filename and parent directory. Patch handles are opaque and must be closed before teardown. Upstream recommends a recursive Git checkout because the Pure Data source is a submodule; a source archive can omit it. Pin a release and submodule revision rather than consuming `master`.

libpd provides `libpd_float()` for sending a scalar to a patch receiver, `libpd_bind()` plus `libpd_set_floathook()` for receiving named float messages, and typed message APIs for other Pd messages. The float hook is one slot per instance and mutually exclusive with that instance's double hook; upstream says to avoid changing it while DSP runs. Hooks therefore need installation before processing and must do bounded work; they should copy data into host-owned bounded state, not call DAW control code synchronously.

The libpd change log says its C core became thread-safe in 0.11.0. Its multi-instance API is conditional on building with `PDINSTANCE`/thread support; otherwise `libpd_new_instance()` returns null and instance selection does nothing. The project should still use one owned worker thread as the sole owner of init, patch lifecycle, messages, processing, and destruction. This follows the DAW's foreign-code and callback ownership rules; it is a stricter host policy, not a claim that upstream libpd is inherently single-threaded. Do not call libpd from the hardware callback. See the [upstream change log](https://github.com/libpd/libpd/blob/master/CHANGES.txt) and [instance API](https://github.com/libpd/libpd/blob/master/libpd_wrapper/z_libpd.h).

The libpd repository's `LICENSE.txt` identifies the Standard Improved BSD License. The bundled Pure Data source is a submodule with its own license file; externals can carry additional per-file licenses. Any future build or redistribution must preserve applicable notices for libpd, the exact Pd submodule revision, and each compiled external. See [libpd's license](https://github.com/libpd/libpd/blob/master/LICENSE.txt), [the Pd submodule license](https://github.com/pure-data/pure-data/blob/master/LICENSE.txt), and [the repository layout/build guidance](https://github.com/libpd/libpd).

## T12b1 block/message proof

`native/puredata/block_probe.py` is an owned child diagnostic using the public libpd float API. It opens the checked-in patch and a checked-in abstraction from separate private directories, sets only the explicit abstraction search path, and verifies 64-frame stereo blocks at 48 kHz. Patch-local `$0` receivers accept frequency/amplitude bases; patch messages echo the float32 values through bound hooks before DSP. Missing receivers reject. At frame 24,576, bases change from 440/0.1 to 660/0.05. Host input supplies distinct left/right offsets, and output measurements verify both the tone and stereo input routing. Hook echo is fixture evidence, not arbitrary native parameter introspection.

One child thread owns initialization, messages, patch open/close, DSP and instance destruction. It disables DSP, unbinds receivers, closes the patch and frees each instance; recreating the instance reproduces the full sample digest. `libpd_num_instances()` returns to the one main instance after each pass. This proves recreation of this fixture, not simultaneous-instance isolation. The parent bounds logs/report to 64 KiB and time to 15 seconds, validates signal evidence, and reaps its process group on exit, failure, timeout or SIGTERM/interrupt. Deliberately escaped descendants are outside containment.

## Pinned build and measured evidence

Tested on macOS arm64 with **libpd 0.16.1**, commit `ba0dc63262901d658af8bbda5e619a60fa975e78`, and its Pure Data submodule `f009fd8d7b537e209e09898d487fdf1bf547da2b` (headers report Pd 0.56.5). Sources and the locally built library remain under ignored `output/`; no system installation or dependency binary is committed. Reproduce the tested configuration:

```sh
git clone --branch 0.16.1 --recurse-submodules https://github.com/libpd/libpd.git output/libpd-runtime/source
make -C output/libpd-runtime/source -j4 UTIL=false EXTRA=false MULTI=true DOUBLE=false
DAW_LIBPD_LIBRARY="$PWD/output/libpd-runtime/source/libs/libpd.dylib" python3 native/puredata/block_probe.py
DAW_LIBPD_LIBRARY="$PWD/output/libpd-runtime/source/libs/libpd.dylib" python3 -m unittest native.puredata.test_blocks
```

Verify both checkout revisions before building. `MULTI=true` enables `PDINSTANCE` and `PDTHREADS`; `DOUBLE=false` retains default internal float32. The public interleaved float API and float message/hook signatures are used without exposing internal Pd structures. `UTIL=false EXTRA=false` omits optional wrapper utilities and bundled extra externals. Standard built-in objects remain available, including objects with filesystem/network effects; this is not a patch sandbox. Arbitrary externals, user assets and unsupported platforms remain unverified.

The first real-library run processed **768 blocks / 49,152 frames per pass**, twice, with matching SHA-256 `46fbd9d850e155ca8efb583de4226100a1a8ff275d6a3e9db1c516b7b46bddcc`. Measured frequency was 440.003/660.005 Hz, peak 0.100000004/0.049999999, and RMS ratio 0.500016. Maximum channel-offset error was 6.26e-9. No audio hardware or DAW callback was opened. All 12 boundary/runtime tests pass, including missing/invalid libraries, patch/report bounds, diagnostic overflow, deadline/descendant cleanup, SIGTERM cancellation and unknown-object rejection. Portable Rust fmt/clippy/tests also pass.

Preserve [libpd's pinned BSD-style license](https://github.com/libpd/libpd/blob/ba0dc63262901d658af8bbda5e619a60fa975e78/LICENSE.txt) and [Pd's pinned license](https://github.com/pure-data/pure-data/blob/f009fd8d7b537e209e09898d487fdf1bf547da2b/LICENSE.txt), plus individual-file notices (including IRCAM notices on compiled expression objects), before redistribution. This project does not bundle the library. A redistribution inventory remains a separate gate.

## T12b2: prepared Pure Data sources (implemented)

Schema v8 embeds a Pd patch, an explicit list of named abstractions, finite duration, source gain, and named scalar receiver bases with saved 64-frame-aligned step points. The saved device is available through the JSONL session/render path; the standalone block diagnostic above remains separate. Loading/replacing prepares every Pd source before committing the session or revision. A failed library load, missing receiver, worker timeout, malformed PCM or process failure preserves the active state. The owned worker has a 15-second deadline and converts validated stereo float32 output to float64 PCM; Rust validates and caches it by saved source inputs and applies device/source gain and track effects on the Rust side.

The source contract limits patch plus abstractions to 60 KiB, abstractions to 16 with unique ASCII filenames, controls to 64 per source, all source points to 512, and the shared SC/Csound/Pd source pool to four tracks and ten summed seconds. `$0-` control names resolve against the opened patch's dollar-zero identity; other receiver names pass through unchanged. A receiver must exist, and `libpd_float` must accept the saved scalar. This is a delivery check, not arbitrary native-value readback. Patch initialization actions finish before saved bases/frame-zero overrides are sent, then DSP begins; events are applied at 64-frame boundaries. Initialization-rate behavior is not guaranteed. The worker runs with zero-filled stereo input, outputs stereo at 64-frame blocks, and trims the final partial block. Preparation uses an absolute `DAW_LIBPD_LIBRARY` built with multi-instance support; optional `DAW_LIBPD_PYTHON` and `DAW_LIBPD_WORKER` choose absolute Python and worker paths. The tested library is 0.16.1. GUI import remains unavailable; T12b4 below adds explicit live Pd playback. Prepared native playback is rate-matched.

`examples/puredata_tracks_demo.py` uses the checked-in patch and abstraction in two schema-v8 tracks, saves/reloads them, checks the 440-to-660 Hz change and combined source/effect gain, and optionally performs a muted native prepared-playback callback check. The primary pass has observed 2,048 submitted muted callback frames and clean resource release. All 11 worker/source integration tests pass, including mixed Csound/Pd preparation, 48,001-frame partial blocks, 44.1 kHz, frame-zero overrides, missing receivers/objects/abstractions, invalid PCM and the 15-second descendant cleanup deadline. Eight Rust schema/transaction tests and the prepared-cache gain/seek/loop test pass. Portable/native/all-feature Rust fmt/clippy/tests and the baseline demo pass; the all-feature binary is restored. HTTP bridge tests pass (31), including format-v8 rejection; browser player/editor tests pass (24). The 12 libpd block tests and nine Csound source regressions also pass. Callback evidence remains separate from acoustic verification.

## T12b3: live fixed-queue production

`native/puredata/stream_worker.py` calls the same concrete libpd block adapter on one owned child thread, publishing each block as it is processed. It does not prepare a whole PCM source before streaming. It reuses `native/csound/queue_api.py` and the tested float64-to-float32 producer bridge; historical Csound/SC symbol names identify that existing queue ABI, not the active DSP runtime. No new processor trait, ABI or DAW command is introduced.

The queue is fixed at 48 kHz, two channels, 64 frames per block and 64 slots. A full queue applies bounded backpressure without overwriting unread samples; a stalled consumer fails after two seconds. Readiness follows publication of four blocks (or all blocks for shorter sources). Saved receiver events retain the schema-v8 semantics. Source gain is not applied by this diagnostic; the integrated transport applies gain/effects in Rust. The final partial block is zero-padded for the queue and trimmed in returned audio. The paced diagnostic reader compares SHA-256 digests over complete padded blocks, checks exact publication/consumption counts and verifies release by acquiring a fresh producer lease after the worker exits.

A repeated one-second fixture run consumed **750 blocks / 48,000 frames**, with producer/consumer SHA-256 `0c07da7f61d9d6dda03a1636bbb99bf9b12adf0047e44558e40b4071eec3a18f`. Frequency measured 439.997/660.015 Hz and RMS 0.0707106/0.0353553. The recorded run had 580 backpressure retries. These are paced diagnostic measurements, not callback latency or acoustic evidence. Initialization, patch search paths, messages, hooks, DSP and destruction remain on the owned libpd thread. The parent limits log/report sizes and time, and reaps the owned process group on success, failure, timeout or cancellation. Forced termination relies on process resource cleanup rather than reporting normal libpd teardown.

Verification: all 14 stream diagnostic cases pass; the CLI SIGTERM process-inventory case was run separately with host access after the sandbox denied `ps`. Coverage includes matching signal/event digests, source gain left unapplied, 48,001-frame padding/trimming, restart/backpressure, producer lease release, malformed/symlink/oversized reports, both log limits, missing receiver/object, stall, producer death, cancellation and deadline/descendant cleanup. The 12 libpd block tests and four existing producer ABI tests pass. Rust fmt/default clippy/tests and the baseline scripting demo pass; the all-feature binary is restored. No hardware callback or acoustic check is part of this diagnostic.

## T12b4: native live transport

The concrete Rust Pd owner starts `stream_worker.py` with private job/queue/report files and compile/start/stop gates. The libpd owner validates the patch, abstractions and receivers before publishing `begin.compiled`; only after all sources initialize does the Rust session worker release the start gates. Native Play acknowledges after the final callback ring is prefilled. The hardware callback reads that ring and does not initialize or call libpd. `transport.play` with `source_mode:"live"` accepts schema v8, mixes Pd/SC/Csound with built-in tracks and gain-only effects, and preserves prepared playback as the default. Source gain, effects and automation remain in Rust.

Each live Pd source has its own process and queue. Duration is capped in the private snapshot to requested playback frames and later control events are removed from that snapshot only. The native mixer consumes exact final partial frames and silence after source end. Natural completion checks the child exit, bounded completion report and actual queue publication count before reporting success; malformed reports or post-final child errors cannot be treated as clean completion. Stop/EOF request owner-thread DSP disable/patch close/instance teardown, then bound foreign hangs and reap the owned process group. Failures stop the whole live session, release the other sources and return structured errors. Saved model/revision remain unchanged by playback or rejected commands.

The muted two-Pd-source example delivered **48,000 source/callback frames**, matching digest `c3c34caf9355aaa5`, zero source underruns and peak 0.0250000004. RMS quarters were 0.0176777, 0.0176777, 0.00944941 and 0.00883883, confirming the saved amplitude change through source/effect gain. Both worker PIDs were reaped. This is callback evidence on the MacBook Air output device, not acoustic verification or a sustained latency/drift guarantee.

Verification: all 13 native Pd transport tests and nine existing Csound transport tests pass, including mixed runtimes, duration boundaries, rollback and owned fault cleanup. All 11 prepared-source and 14 queue tests pass, as do 31 GUI bridge and 24 browser player/editor tests. Portable/native/all-feature Rust checks and the baseline demo pass; the final native/all-feature library checks cover the completion count guard, and the all-feature binary is restored. Twelve existing SC transport/control regressions pass. Two optional live VST worker tests remain ignored.
