# SuperCollider: owned NRT jobs before track devices

The first integration is `supercollider.render`, a synchronous JSONL job that turns a prepared binary OSC score into a fresh stereo PCM16 WAV. It is available on Unix with an explicitly configured absolute `DAW_SCSYNTH` executable. It does not change the active session, revision or transport, and does not expose a GUI route. Compiled support and executable configuration are separate capability fields; neither proves installed UGen compatibility.

Each job reads at most 1 MiB from a regular score file and copies that snapshot into a private temporary directory. Scores use big-endian length-prefixed OSC bundles, with relative fixed-point timestamps starting at zero, in nondecreasing order, ending between 0.001 and 10 seconds. There are at most 16384 records and 65516 bytes per bundle. The initial contract accepts flat, string-address OSC messages with scalar/string/blob tags `i`, `f`, `s`, `S`, `b`, `h`, `d`, `c`, `T`, `F`, `N`, `I`. Floating arguments must be finite; lengths, padding, UTF-8 strings and trailing bytes are validated. Integer command addresses, nested bundles and OSC arrays are not accepted yet.

The engine launches `scsynth -N` with argument arrays, stereo output, no input, a 64-frame block, disabled automatic SynthDef loading and a private restricted path for file-accessing OSC commands. A score must carry its own SynthDefs through `/d_recv`; external asset loading needs a later explicit asset contract. No language interpreter or hardware stream is launched. This is an offline process boundary, not an embedded device or a security sandbox: installed UGens and the configured executable run with the caller's permissions.

The owned child process group has a 15-second deadline and separately bounded 64 KiB stdout/stderr. Exit failure, reported server errors, oversized diagnostics, missing/invalid WAV, wrong format/rate, and unexpected frame counts fail with `runtime_error`. Some server command failures can return exit status zero; captured diagnostics are also checked. The final WAV is published only after the child is stopped and the complete PCM payload is validated. Destination creation is exclusive, and a failed write removes only the file created by that job. Existing outputs are preserved.

NRT writes whole blocks. The adapter accepts up to 128 trailing frames and trims them to `round(last_timestamp * sample_rate)` frames. This produces a stable duration; it does not promise that every UGen or OSC operation is sample accurate. Rates are 8000–192000 Hz. The reference fixture builds a small SCgf-v2 SynthDef using Control, SinOsc, multiplication and stereo Out. It uses no third-party UGens and compiles no SuperCollider language source at runtime.

Schema v6 integrates a saved runtime program and its named controls/events into the authoritative track model. An exported WAV can already be placed in an audio-clip project by a script, but that alone is not a programmable track device. Interactive OSC ownership, create/free completion acknowledgements and live audio routing remain separate acceptance work for T11.

Sources: [SuperCollider NRT guide](https://doc.sccode.org/Guides/Non-Realtime-Synthesis.html), [SynthDef binary format](https://doc.sccode.org/Reference/Synth-Definition-File-Format.html), and the installed 3.14.1 `Score.sc` and `scsynth -h`. The guide establishes that NRT consumes a score without realtime networking, and the installed implementation confirms the `-N` argument order and size-prefixed bundle encoding. No runtime binaries are bundled; SuperCollider's [source and license](https://github.com/supercollider/supercollider) remain upstream.

OSC validation checks framing and scalar/string/blob encoding, plus the SynthDef file header for `/d_recv`. It does not interpret every server command or UGen graph. A successful result proves that a bounded WAV was produced and validated; NRT provides no per-command completion acknowledgements, and commands that fail silently in the runtime cannot all be detected. Interactive completion handling remains required before claiming the full T11 control contract.

Portable program inspection uses `supercollider.inspect` before the saved-device slice. It decodes one complete bounded SCgf-v2 program and extracts actual named control defaults, including array spans. Finite numeric fields, bounded counts, native control output spans and backward graph references are checked. Unknown UGen class names remain inspectable because installed UGen compatibility requires runtime evidence. The inspector does not substitute for runtime preparation before a future session commit. See the protocol for the exact accepted subset and limits.

Saved source preparation now uses the same owned NRT process/validation boundary with a float32 internal WAV. This avoids clipping source headroom before serial effects and the DAW master. The original standalone command still publishes PCM16. Programs are embedded rather than referred to by external paths; a bounded cache identifies the exact program/control/event/rate inputs and is excluded from persisted JSON. Track gain belongs to the DAW and does not invalidate runtime PCM. Preparation occurs before session commit; live VST3 source preparation occurs on the caller before its foreign DSP worker starts. The native callback uses existing preloaded audio scheduling and never launches or calls SuperCollider. Control changes are NRT events, whose effective precision depends on the UGen and server block. Interactive server ownership and audio routing remain T11c work.

Base control overrides are part of synth creation, because initialization-rate controls latch at that point. A frame-zero point replaces its creation value. Known scalar/init control slots reject subsequent points rather than silently ignoring them; the inspector retains internal rate information without changing its public metadata shape.

## Interactive server proof (T11c1)

`native/supercollider/live_probe.py` starts only its own macOS `scsynth`, with `-u 0 -B 127.0.0.1`, no inputs, 48 kHz, disabled default SynthDefs/Rendezvous, and a private restricted filesystem path. It discovers the allocated UDP port from that exact child's PID using numeric `lsof` output. There is no attach mode and no instruction to stop other servers. Requests are serialized and replies must come from the owned endpoint; OSC encoding/decoding, command waits, startup and total duration are bounded. Diagnostics are capped at 64 KiB combined. Cleanup stops the owned process group, reaps the child and releases sockets/readers/temp files on success or failure.

The proof awaits `/done` for definitions and buffers, `/n_go`/`/n_end` for create/free, reads back changed native controls, then captures their actual audio consequence. A sine writes private buses 16/17, while a second `In`/`RecordBuf` synth captures 4096 stereo frames. Before and after `/n_set`, measured peaks are approximately 0.1 and 0.05, RMS approximately 0.07056 and 0.03531, and matched frequencies are 440 and 660 Hz. A separate output-bus capture is all zero. `/quit` is acknowledged and the child exits with status zero. This establishes finite live-server control/audio and lifecycle evidence; it does not send runtime audio through the DAW callback or prove acoustic delivery. The result explicitly reports `streaming_audio:false` and `daw_transport:false`. No product JSONL methods or capability flags are added.

Run with host audio and loopback access:

```sh
DAW_SCSYNTH=/Applications/SuperCollider.app/Contents/Resources/scsynth python3 native/supercollider/live_probe.py
DAW_TEST_SC_LIVE=1 DAW_SCSYNTH=/Applications/SuperCollider.app/Contents/Resources/scsynth python3 -m unittest native.supercollider.test_live_probe
```

The finite capture reads 256 samples per OSC response. This is a diagnostic: the [server command reference](https://doc.sccode.org/Reference/Server-Command-Reference.html) limits `/b_getn` to small sample queries, and it is unsuitable for continuous PCM transport. Native control readback proves stored control state; only the captured changed samples provide DSP evidence here. The [installed BufIO implementation](https://github.com/supercollider/supercollider/blob/Version-3.14.1/SCClassLibrary/Common/Audio/BufIO.sc) provides the exact `In`/`RecordBuf` input layout used by the generated fixture.

## Streaming decision and remaining gates (T11c2)

The pinned 3.14.1 [scope buffer implementation](https://github.com/supercollider/supercollider/blob/Version-3.14.1/common/scope_buffer.hpp) has three exchanged regions and a changed flag, rather than a sequence-retaining FIFO. `push` replaces the staged region; `pull` selects it without a per-block sequence acknowledgment. Inference from those operations: a slow consumer can miss intermediate publications. The visualization scope path must not be advertised as lossless DAW audio routing.

The next experiment is a project-owned UGen and fixed shared-memory SPSC queue. Create/map and validate memory during server/plugin initialization, before audio execution; do not mmap/open/allocate in a synth constructor unless its thread context is proven safe. The UGen processing function must perform only bounded copies/lock-free atomics, fail explicitly on overflow and publish frame sequence/counters. A DAW-owned non-realtime drainer must consume that stream into the existing fixed callback queue. The hardware callback must never call SuperCollider, OSC, filesystem APIs or foreign initialization.

Before product integration, prove: ABI/version/rate/channel/block/nonce validation, exactly one producer, no constructor/process allocation or OS calls, multi-process ordering/wraparound/overflow, child crash and timeout cleanup, streaming sequence continuity, measured control-to-audio latency, and source-to-effect-to-native-callback routing. Capture and silence hardware buses after copying source audio, and measure that mute path. Multiple saved programs can share names; establish isolated instances or explicit identity rewriting before claiming multi-track correctness. Define pause, stop, automation and update acknowledgments against the actual stream. Native callback evidence remains distinct from acoustic verification. T11c is incomplete until these gates pass; scope or OSC success alone does not complete it.

## Fixed queue prototype (T11c2a)

`stream_ugen.cpp`, `stream_queue.hpp`, `stream_reader.cpp` and `stream_probe.py` implement an independent finite streaming diagnostic. No product API, schema, callback or capability flag changes. Tested with the installed scsynth 3.14.1 on macOS arm64: 512 consecutive queue blocks, 32,768 stereo frames at 48 kHz; early PCM matched 440 Hz / peak 0.1, late PCM matched 660 Hz / peak 0.05 following OSC control changes. Captured output buses remained zero. This proves the custom process boundary for the fixture, rather than DAW playback or acoustic delivery.

The ABI is a 32,960-byte, owned regular mode-0600 file with magic/version, nonce, rate 48,000, block 64, channels 2, capacity 64 blocks, and separate cache-line-aligned read/write counters. Both sides use the same compiled C++ header and always-lock-free 32-bit atomics. Acquire/release publication and reclamation retain samples until consumed; unsigned indices wrap. Exactly one UGen producer and one drainer consumer may claim leases. Overflow, duplicate producers, wrong unit layout or nonfinite producer samples latch an explicit fault. The non-realtime drainer polls and performs bounded exclusive file output; it is not an audio callback. A two-process pattern test validates every sample across 12,000 blocks and counter wrap. Identity/rate/layout/nonce/permissions and output-preservation tests pass. Real-server overflow and duplicate-producer cases fail without publishing partial output.

Mapping, validation, memory locking and page touching occur in plugin load. Pinned [World startup](https://github.com/supercollider/supercollider/blob/Version-3.14.1/server/scsynth/SC_World.cpp#L291-L298) invokes plugin loading before [driver setup/start](https://github.com/supercollider/supercollider/blob/Version-3.14.1/server/scsynth/SC_World.cpp#L406-L424). [Graph first calculation](https://github.com/supercollider/supercollider/blob/Version-3.14.1/server/scsynth/SC_Graph.cpp#L473-L488) invokes constructors in the realtime graph path: our constructor/destructor only validate or claim/release atomics, and processing only clears a fixed output, checks finite input and copies one block. The unit forbids input/output aliasing; otherwise clearing its unused output can erase an input. The [UGen guide](https://doc.sccode.org/Guides/WritingUGens.html) establishes callback constraints. The mapping stays alive until the owned server process exits; no callback unmaps it. Explicit node destruction releases the producer lease, but abrupt child exit can leave counters/leases set. Each launch gets a fresh disposable queue; never reset/reuse one after a crash.

A colon-separated `-U` argument includes only bundled standard UGens and the private diagnostic directory, excluding user extension discovery. See the pinned [path delimiter](https://github.com/supercollider/supercollider/blob/Version-3.14.1/common/SC_StringParser.h#L24-L29) and [loader](https://github.com/supercollider/supercollider/blob/Version-3.14.1/server/scsynth/SC_Lib_Cintf.cpp#L165-L203). Build against an official Version-3.14.1 include tree, matching the installed server architecture. SDK headers/runtime binaries are not committed; generated plugins stay under ignored output. The SDK's GPL notices and upstream COPYING remain applicable to compiled plugin distribution; this diagnostic does not complete a distribution review.

```sh
python3 native/supercollider/build_stream.py --sdk /absolute/path/to/supercollider-3.14.1
DAW_SCSYNTH=/Applications/SuperCollider.app/Contents/Resources/scsynth python3 native/supercollider/stream_probe.py
DAW_TEST_SC_STREAM=1 DAW_TEST_SC_LIVE=1 DAW_SCSYNTH=/Applications/SuperCollider.app/Contents/Resources/scsynth python3 -m unittest native.supercollider.test_stream native.supercollider.test_live_probe
```

Ten combined tests passed, along with the existing Rust fmt/clippy/test checks and an all-feature build. The independent prototype does not alter the running preview. Remaining T11c2b gates: connect to the DAW's callback queue/effects, measure sustained sequence continuity, latency and clock drift, define pause/stop/update semantics, handle child death/deadline at that integration boundary, and isolate multiple saved program names. No x86_64/Linux, arbitrary SynthDef or long-running stream compatibility claim yet.
