# Csound: owned offline CSD jobs

T12a adds `csound.render` as a real standalone JSONL adapter. It follows the owned child/deadline/exclusive-output conventions of SuperCollider NRT without adding a speculative processor abstraction. No schema change is required; session state is untouched. Saved CSD orchestra/score text owns the instrument parameters and finite schedule. The demo changes score p-fields from 440 Hz/0.1 gain to 660 Hz/0.05 and measures the resulting audio.

The runner snapshots a bounded UTF-8 CSD, starts the explicit Unix `DAW_CSOUND` executable in a private directory, substitutes empty `CSOUND6RC`/`CSOUND7RC`, ignores CSD launch options and requests stereo PCM16 output. Stereo is checked from the resulting file; programs must declare two output channels. Sample rate and `ksmps=1` are imposed to give an exact frame-count contract. This can change the timing/performance of programs written for another control-block size; this first adapter promises only the checked fixture, not arbitrary CSD compatibility. A requested duration validates the finished output, not the score syntax. Overlong/infinite programs fail output/deadline checks.

The owned group is terminated on failure/deadline and after direct-child exit, preventing ordinary descendants from holding diagnostic pipes open. Processes that deliberately escape their group and arbitrary opcode side effects are outside containment. No foreign code is executed by an audio callback, and no audio hardware is required for the fixture. Full WAV validation precedes exclusive publication. Later cancellable jobs should preserve these ownership/publication rules.

## Csound 7 block/control proof (T12a2)

`native/csound/block_probe.py` loads an explicit absolute `DAW_CSOUND_LIBRARY` only inside a fresh owned Unix child process. It performs the checked-in `block_fixture.csd` through the pinned Csound 7 double-sample ABI. The diagnostic rejects other major/sample-size ABIs before instance creation; required symbols must exist. Csound 6 uses different signatures and is intentionally not accepted. This does not add a Rust protocol method, capability flag, saved device or GUI control; `csound_offline.native_playback` remains false.

One child thread owns library initialization, instance creation, compilation, control-channel access, each DSP block and reset/destruction. `csoundInitialize` disables Csound signal/atexit registration. An empty opcode search directory limits automatic third-party module loading for this fixture, and owned empty rc files/private cwd avoid user launch configuration. The program uses built-in opcodes. `csoundSetHostAudioIO` is set before compilation/start to disable Csound backend sound I/O; no hardware stream or WAV file is opened. This is trusted native code, not a sandbox or an assertion that arbitrary code cannot open a device.

The program declares 48 kHz, 64 frames per control block, stereo input/output and `0dbfs=1`. The host verifies those values before accessing buffers. It obtains borrowed `spin` before each perform call and overwrites all 128 input samples with left `0.01`/right `-0.02`. It copies borrowed `spout` immediately after each call, before another perform/reset. All output must be finite; channel subtraction must match `0.03` within `1e-12`. No pointer survives reset/destruction. All Python allocations, hashing and signal analysis are diagnostic work on the owning thread, never hardware callback work.

Native frequency/gain channels are set and read back exactly before start, then changed at frame 24,576 between block calls. The host captures 768 blocks/49,152 frames, verifies clean score completion, resets and recompiles the same instance, repeats the operation and compares the full reports/sample SHA-256 digests. Finally it resets/destroys the instance before reporting success. Failure reporting and child group/deadline/diagnostic cleanup are owned by the parent. The final report is a bounded private JSON file validated by the parent; stdout contains only the successful JSON report. Errors emit structured `runtime_error` JSON to stderr and return nonzero.

The tested 7.0.0-beta.17 library produced 440.008/660.002 Hz, peaks 0.100/0.050 and centered RMS 0.070714/0.035351; RMS ratio was 0.499922. Both passes produced digest `b62f18af878f5a119fd3e4b7da45de7fc4a21ad6f53080f4276f6338aba49e55`. Performance runs without wall-clock pacing: this demonstrates changes reaching successive DSP blocks, not real-time delivery, worker deadline performance, audio callback safety or acoustic output. Queue backpressure, startup prefill, native control acknowledgments and saved-session transactional validation are the next integration gates.

Run with:

```sh
DAW_CSOUND_LIBRARY=/absolute/CsoundLib64 python3 native/csound/block_probe.py
DAW_TEST_CSOUND_BLOCKS=1 DAW_CSOUND_LIBRARY=/absolute/CsoundLib64 python3 -m unittest native.csound.test_blocks
```

All nine block-diagnostic tests pass, including the real-library signal/reset and invalid-compilation cases. Fake children cover missing/invalid library selection, strict report validation (including nonfinite values), malformed/oversized/special-file results, stdout/stderr overflow, deadlines and descendant-pipe cleanup. Portable Rust fmt/clippy/tests and the baseline demo pass; the all-feature binary remains available.

The extracted official macOS framework library works directly without the relocated executable's `DYLD_FRAMEWORK_PATH` requirement. No library binaries or third-party headers are committed. The dependency notices above continue to apply. ABI sources are the shipped and pinned [csound.h](https://github.com/csound/csound/blob/7.0.0-beta.17/include/csound.h) and [csound_rtaudio.h](https://github.com/csound/csound/blob/7.0.0-beta.17/include/csound_rtaudio.h); the older [6.18 API](https://csound.com/docs/api/group__RTAUDIOIO.html) explains buffer ownership but does not define this v7 binding.

## Schema-v7 saved Csound sources (T12a3a)

Schema v7 embeds a bounded CSD string, finite duration, source gain, and named scalar control bases with saved step points. `native/csound/source_worker.py` uses ctypes against the explicit absolute `DAW_CSOUND_LIBRARY`; the Unix Rust host owns its child process, deadline, output bounds, diagnostics and cleanup. `DAW_CSOUND_PYTHON` optionally selects an absolute executable (otherwise `python3`); `DAW_CSOUND_WORKER` optionally selects an absolute worker path (otherwise this checkout's worker is used). Csound 7 double-sample ABI is required. The worker disables host audio I/O, uses empty owned rc/opcode search configuration, and accepts only the validated finite result stream; these measures limit ambient configuration but do not sandbox trusted CSD/opcode code.

The source must match the session sample rate and declare stereo output, `0dbfs=1`, and `ksmps=64`; up to two input channels are zero-filled. Prepared output is stereo float64. The worker performs complete 64-frame blocks and copies only the requested number of frames from the final block. Saved points are 64-frame aligned. It starts Csound before querying/applying declared scalar input controls, so frame-zero values reach the first perform call but initialization-rate effects are not guaranteed. This saved control shape deliberately does not claim init-rate support. The schema/source limits are 60 KiB of program text, 64 controls per source, 512 points, four SC+Csound sources and ten summed source-seconds. Decoded source PCM shares the 128 MiB audio asset budget.

All runtime sources prepare transactionally on session replacement/load, before the active session or revision changes. Prepared float64 PCM is cached without source gain in its key; Rust applies source/track gain and existing effects during render or prepared native playback. A gain-only `session.edit` can reuse the cached frames; a deserialized full replacement or reload requires fresh preparation. Session saves contain the source definition/control data, never prepared PCM. `csound.render` remains a separate standalone PCM16 job using executable `DAW_CSOUND`; saved Csound tracks use library `DAW_CSOUND_LIBRARY`. The GUI rejects schema-v7 imports, and explicit live runtime transport now accepts v6/v7 with the limits below. No Csound instance or interactive Csound control channel remains active during prepared playback.

Verification: six Rust schema/preparation tests and nine Python source-worker tests pass, including three real Csound 7 cases plus mixed SuperCollider/Csound routing/budget and owned-worker deadline/descendant cleanup/state-preservation coverage. `examples/csound_tracks_demo.py` saved/reloaded two sources and rendered the 440/660 Hz fixture through serial gain, with peak 819. Its muted native run submitted 2048 callback frames and released transport resources; this is callback evidence, not acoustic proof. The parent integration pass also confirmed 27 GUI bridge tests and ten SuperCollider source tests (one optional hardware test skipped), and portable/all-feature Rust fmt, clippy and tests. The standalone Csound suite's prior 13-test run with three real-runtime cases remains documented above; the latest environment without `DAW_CSOUND` ran ten tests with three runtime skips.

## Csound producer queue diagnostic (T12a3b1)

`native/csound/build_queue.py` builds a macOS arm64 bridge that combines a Csound-owned producer with the existing SuperCollider fixed-queue ABI. The queue layout and consumer API are unchanged. Blocks are 64 frames, stereo float32 at 48 kHz, with 64 slots. `stream_probe.py` starts the producer as an owned child, waits for publication of a prefill of up to four blocks, then consumes at the matching pace without opening hardware or starting DAW transport. It bounds the run to 15 seconds, monitors diagnostic files at 64 KiB and each JSON report at 4 KiB, and reads reports through bounded nonblocking/no-follow file descriptors. The real producer also enforces a 64 KiB file-size limit for diagnostic/CSD writes. The producer waits and retries on a full queue, fails after two seconds without consumer progress, and never overwrites unread blocks. Exclusive producer/consumer leases, nonce and file checks guard queue use; Normal completion and handled worker errors reset and destroy Csound on its owning thread. Parent cancellation/deadlines terminate and reap the owned process group instead; failed queues are discarded rather than reused. Samples are copied from Csound's double buffer, checked finite and float32-representable, then converted to float32. The shared preparation worker performs the Csound block loop outside any hardware callback.

One installed Csound 7 run consumed 750 blocks (48,000 source frames); producer and consumer SHA-256 matched: `553babc97e5c75361f148f6e166086d7ffde91fa2d60f230baa033b7664634cb`. It recorded 684 backpressure waits (machine-dependent). The captured sections measured 439.9966 Hz and 660.0151 Hz, RMS 0.0707106766 and 0.0353553386, and peaks 0.1 and 0.05. This establishes finite source-to-queue continuity, saved control changes and bounded backpressure for the diagnostic. `hardware_audio` and `daw_transport` are false: it provides no hardware callback, DAW transport, acoustic, or live-control acknowledgment evidence. Eight stream tests and four producer ABI tests pass. Coverage includes installed-library signal/restart, partial final blocks, source/control errors, bounded typed startup reports, stalled consumers, producer death, cancellation/descendant cleanup and CLI SIGTERM worker reaping. The shared-loop regression pass passed all nine saved Csound source tests and seven existing SC bridge tests. Portable Rust fmt/clippy/tests and the baseline demo pass; the all-feature binary is restored.

Build and run on macOS arm64 with the tested Csound 7 double-sample library:

```sh
python3 native/csound/build_queue.py
DAW_CSOUND_LIBRARY=/absolute/CsoundLib64 python3 native/csound/stream_probe.py
```

T12a3b2a connects this producer to native transport below; T12a3b2b remains open for live Csound control acknowledgment. The diagnostic queue path does not change protocol capabilities; the GUI continues to reject schema-v7 imports. Keep callback evidence separate from acoustic verification.

The pinned beta runtime also crashed while parsing an early malformed fixture with same-line `<CsOptions></CsOptions>` tags. The owned child contained that failure and preparation preserved the active session/revision. Checked-in fixtures use separate tag lines; the host does not rewrite arbitrary CSD text or promise compatibility beyond the tested programs.

## Live Csound transport (T12a3b2a)

On macOS arm64, explicit JSONL `transport.play` with `source_mode:"live"` starts the owned Csound producer for schema-v7 sources and sends its fixed queue through the Rust worker to the existing native callback ring. A session may contain SC v6, Csound v7, or both, plus the supported built-in tracks; output requires a 48 kHz device, is limited to ten seconds, and accepts gain effects only. The stream worker applies saved Csound control bases and step events. `DAW_CSOUND_LIBRARY` selects the absolute Csound 7 double-sample library. `native/csound/build_queue.py` builds the bridge; `DAW_CSOUND_QUEUE_LIBRARY`, `DAW_CSOUND_STREAM_WORKER`, and `DAW_CSOUND_PYTHON` may select absolute bridge, worker, and Python executable paths. The default bridge is under ignored `output/csound-stream/` and the default stream worker is in this checkout.

The producer starts behind a gate until native transport has established its bounded queues. Csound compilation, initialization, control updates, DSP and teardown stay on the owned producer worker; the Rust worker drains fixed queue blocks and publishes into the callback ring. The callback does no foreign calls, allocation, locking, process or filesystem operations. Status reports the runtime composition as `csound`, `supercollider`, or `mixed`, along with source/callback telemetry. Stop, natural completion and protocol EOF release the native stream and reap owned children. A hung producer can be killed after the bounded two-second stop wait; the release report establishes child reaping and does not assert graceful Csound instance reset after forced termination. Pause/resume, seek, loop and revision-checked live Csound control edits are unsupported; saved controls/events still apply. SC live control edits retain their separate supported semantics.

Nine native Csound transport tests pass, including short and partial source durations, truncation, zero-tail completion, rollback and mixed SC/Csound routing. Twenty-eight combined Csound source/stream/ABI and SC bridge regressions pass, alongside twelve SC live transport/control regressions. Baseline, native and all-feature Rust tests pass; native/all-feature clippy passes after an immutable-loop lint correction. The Csound natural-completion test submitted 48,000 callback frames with matching source/callback fingerprints and zero live source underruns; the SC live demo also submitted 48,000 frames with zero underruns, and the saved-source demo rendered the 440/660 Hz fixtures with peak 819. These checks verify callback and owned-process behavior with the monitor muted. They do not verify acoustic delivery; forced stop cleanup does not assert a graceful per-instance reset after a hung worker. T12a3b2b remains for saved Csound control edits with revision and DSP/callback acknowledgment.
