# Csound: owned offline CSD jobs

T12a adds `csound.render` as a real standalone JSONL adapter. It follows the owned child/deadline/exclusive-output conventions of SuperCollider NRT without adding a speculative processor abstraction. No schema change is required; session state is untouched. Saved CSD orchestra/score text owns the instrument parameters and finite schedule. The demo changes score p-fields from 440 Hz/0.1 gain to 660 Hz/0.05 and measures the resulting audio.

The runner snapshots a bounded UTF-8 CSD, starts the explicit Unix `DAW_CSOUND` executable in a private directory, substitutes empty `CSOUND6RC`/`CSOUND7RC`, ignores CSD launch options and requests stereo PCM16 output. Stereo is checked from the resulting file; programs must declare two output channels. Sample rate and `ksmps=1` are imposed to give an exact frame-count contract. This can change the timing/performance of programs written for another control-block size; this first adapter promises only the checked fixture, not arbitrary CSD compatibility. A requested duration validates the finished output, not the score syntax. Overlong/infinite programs fail output/deadline checks.

The owned group is terminated on failure/deadline and after direct-child exit, preventing ordinary descendants from holding diagnostic pipes open. Processes that deliberately escape their group and arbitrary opcode side effects are outside containment. No foreign code is executed by an audio callback, and no audio hardware is required for the fixture. Full WAV validation precedes exclusive publication. Later cancellable jobs should preserve these ownership/publication rules.

## Runtime evidence and notices

Tested on macOS arm64 with the official Csound **7.0.0-beta.17**, runtime commit `2932c7fd14681493b5db83df3efdda175c1eb116` (June 19, 2026 build). The vendor archive was extracted under ignored `output/`, without running the installer or changing system libraries. Its relocated framework required `DYLD_FRAMEWORK_PATH` for this local test. The archive SHA-256 is `63e9a3a888fa40dc98200683b9914f2afddb539e53925af5a021076add6a660f`. No engine or framework binaries are committed/distributed. Csound 6 startup options informed the implementation, but Csound 6 and other platforms have not been runtime-tested.

The one-second demo measured 440.01 Hz and 660.00 Hz, identical stereo channels, peaks 3277/1639 and RMS ratio 0.500. This is offline digital signal evidence, with no acoustic or DAW live-callback claim. Thirteen controller integration tests pass, including real 44.1 kHz output with conflicting CSD device options ignored and invalid-program rollback. Fake workers cover missing executables, strict params, invalid/oversized input, malformed/oversized/truncated WAVs, diagnostic overflow, deadlines, descendant cleanup and symlink/existing destination preservation. Portable/all-feature Rust checks pass (two existing opt-in live VST3 tests remain ignored). The original GUI previews remain running and their sessions are untouched.

Csound's pinned [COPYING](https://github.com/csound/csound/blob/7.0.0-beta.17/COPYING) contains LGPL-2.1; consult individual source notices for applicability and later-version permissions. The official framework also carries third-party audio/MIDI/network libraries; preserve their individual licenses and notices before any redistribution. This adapter invokes an external caller-provided executable and does not bundle dependencies. Sources: [official release](https://github.com/csound/csound/releases/tag/7.0.0-beta.17), [command flags](https://csound.com/docs/manual/CommandFlags.html), and [pinned rc initialization](https://github.com/csound/csound/blob/7.0.0-beta.17/Top/main.c).
